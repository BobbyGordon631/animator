Describe your extension(s) here before implementing them.
Because the drawing language has only integers and no trigonometry, drawing a circle or a 3D object by hand means approximating every curve with dozens of hand-placed lines. My extension moves that math into the app so that users can draw curved and 3D shapes directly and learn how they work by editing working examples.
 
1. New 2D shapes and trigonometry. I will add Circle(center, radius), Arc(center, radius, from_degrees, to_degrees), Polygon(center, radius, sides, rotation_degrees), and Star(center, outer_radius, inner_radius, points) as new Shape variants and constructors. render.gleam converts each one into points along its outline, so every new shape animates with the same start/end reveal as a Line: a circle traces itself around its edge instead of appearing all at once. I will also add two built-ins, sin(degrees, scale) and cos(degrees, scale), which return round(scale × sin(degrees)) and round(scale × cos(degrees)) as Ints, since the language only has integers. They let users and the presets place things on circles and orbits.
 
2. 3D wireframes. I will add Point3(x, y, z), Line3(start, end), Cube(center, size), and Sphere(center, radius). A new "camera" slider in the control bar sets the viewing angle, and render.gleam rotates every 3D point around the vertical axis and projects it onto the canvas with perspective, so dragging the slider turns the object. A switch next to it changes to freehand viewing, where dragging the drawing itself turns it sideways and tilts it to look from above or below. Because the shapes stay ordinary Path values, users can combine 3D shapes with 2D ones and with shape_slider.
 
3. Preset gallery. The drawing menu will offer presets (circle, star, flower, spiral, cube, solar system, kolam), listed under "new drawing…". Choosing one asks for a name (suggesting the preset's) and saves an editable copy in the library, adding -2, -3, ... if the name is taken. Each preset lists its settings as let lines at the top of draw, written like let sides = 6 // setting 3..12, and a settings panel shows a labeled slider with that range for each one. The convention works in any drawing, including ones users write themselves. Dragging a slider rewrites just that number in the code, so users watch the code and the drawing change together.
 
None of these changes touch Point, Line, Path, the evaluator's core logic, or the tests; existing drawings keep working unchanged.
